What it does

Six things teams use it for, shown as they look in Bothy.

Code

Answers that point at the line.

Bothy indexes the repositories you connect and reads them before it answers. When it changes something, it says which file and which lines, runs the tests in a sandbox and links the change.

Deploys

Production waits for two people.

Set an environment to need two approvals and Bothy holds the deploy until two admins agree. The card shows what will run and who has said yes so far.

Connections

Works where your team already is.

Slack, Telegram, Discord and the web. GitHub for code. Any MCP server for the rest, with each of its actions marked as reading or changing things, so you decide which ones need a yes.

Team memory

Learns how you work, with an admin's say.

When someone asks Bothy to remember something for everyone, it becomes a request. An admin approves the exact words before they shape a single answer.

Schedules

Runs the jobs nobody wants to remember.

Standup summaries, invoice reminders, a weekly pull request digest. Each schedule posts to the chat you pick, and a failed run tells you why.

Refine

A second and third opinion, when it counts.

Turn on Refine and Bothy writes several drafts, checks them against each other and keeps the answer they agree on. The record says how many agreed and what it cost.

Safe before you configure anything.

An agent with your keys and your code should be boring about security. These are the defaults, not add-ons.

Your infrastructure
Bothy runs in your cloud or on your server: one container and one data volume. No telemetry and no auto-update.
An encrypted vault
API keys and tokens are encrypted at rest. Each key goes only to the service it belongs to, and none ever enters a sandbox.
Sandboxed code
Shell and Python run in throwaway containers with no network, a read-only root and no capabilities. Without a sandbox they are off; nothing falls back to the host.
Approval for anything outward
Messages, pull requests, deploys and deletes wait on a card built from the exact action, never from the model's description of it.
An audit log that shows tampering
Every action, approval and sign-in is written to an append-only log with a hash chain.

Install

You need Docker. Bothy listens on this machine only until you decide otherwise.

  1. Start Bothy

    docker run -d --name bothy -p 127.0.0.1:8080:8080 -v bothy-data:/data ghcr.io/rielicat/bothy:latest

    The same image is on Docker Hub as rielicat/bothy.

  2. Open the setup link

    docker logs bothy

    The log prints a one-time link to http://127.0.0.1:8080/setup. It walks you through the owner account, a model provider and your chat apps.

Run code too

The single container chats, uses your tools and opens pull requests. To let Bothy run shell and Python, start it with the compose file, which adds the sandbox sidecar. On AWS, the ECS templates set up the same pair.
